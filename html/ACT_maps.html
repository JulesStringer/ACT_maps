ACT maps

This plugin provides a shortcode which can be configured to display preconfigured maps:

  • WW - Wildlife wardens map
  • CC - Carbon Cutters map
  • AreaCarbon - Impact data

Full set of short code parameters

The full set of short code parameters are given in the following table:

ParameterDescription
ID

ID of the map type to be displayed:

  • WW - Wildlife wardens map
  • CC - Carbon Cutters map
  • AreaCarbon - Impact Data
widthwidth of the map panel
heightheight of the map panel
titletitle for the map
forceshift If set the shift key needs to be held to zoom the map, this defaults to true so only needs to be set to false to turn this functionality off

How map layers are defined

In the plugin package is a maps directory, which contains sub-folders for each map ID which contain:

  • groups.json file defining the layers used
  • {ID}.html an html page to render the frame of the map
  • {ID}.js JavaScript to implement the behaviour of the map

proxy.php

The groups.json config file references a url which points to geojson data for the map.

In most cases the url uses the proxy.php script to turn a layer id into map data

This has a number of advantages:

  • It enables the code within the plugin to be unchanged to use maps stored outside the plugin directory. Storing maps in the plugin directory is undesirable as it make maintaining the map data harder, and would make merging with data maintained by ACT_admin impossible.
  • Map files can only be referenced without generating CORS errors if they are in the same domain as the calling page.

The following example shows the use of proxy.php for the WW map layer in the WW map type: 

                
    "url": "../../proxy.php?layer=WW"

proxy.php looks up the details of the layer WW in MAPDATA/layers.json which has entries as follows: 

                
                    {
                        "WW":{
                            "location": "local",
                            "path": "WW/WildlifeWardenArea.json"
                        },
                        "Rivers":{
                            "location": "remote",
                            "url": "https://sites.stringerhj.co.uk/mapdata/natural_environment/rivers.json"
                        }
                    }
  • location can be local or remote.
    • local is a path within the directory defined by MAPDATA
    • remote is a url
  • MAPDATA is a directory containing mapping data which is defined as within wp-config.php,e.g 
    
        define( 'MAPDATA' , '/var/www/stringerhj.co.uk/ACT/public_html/mapdata/');

Loading maps

Most mapping is derived from freely available layers from OS Open data in standard formats including shp. Often the download package covers a larger area than is needed for our purposes. As server space is limited we don't want to load more than is necessary. Ideally we want mapping in geojson format for display, so a conversion is needed. A widely used utility for performing this conversion is ogr2ogr which can perform a filtered conversion between formats including shp to geojson.

It is not practical to install ogr2ogr on siteground (or other web hosting) as root access is not generally available, this is needed to perform the installation.

This means that map processing needs to be done on another machine prior to uploading the processed maps to siteground.

See loading maps for further information on loading maps.

Synchronising maps with a remote server

As is discussed above mapping is generated on a separate server. The proxy mechanism hides this location from the rest of the map display software described here. It may still be desirable to localise maps that are sourced locally. This can be configured by scheduling syncmaps.php in the mapdata directory to run periodically. This checks the versions file in monitored directories and takes a local copy of any maps that are changed. This uses the url and path fields in MAPDATA/layers.json to determine which maps are downloaded.

If a layer's entry in MAPDATA/layers.json has both url and path fields, then the versions.json file at both locations is checked for the version of the file and if these differ the version from url is copied to path and the version updated. example: 

            
    {
        "WW":{
            "location": "local",
            "path": "WW/WildlifeWardenArea.json"
        },
        "Rivers":{
            "location": "local",
            "url": "https://sites.stringerhj.co.uk/mapdata/natural_environment/rivers.json",
            "path": "natural_environment/rivers.json"
        }
    }

Here the Rivers layer is maintained on a remote site, but also has a local path, this means that it will be maintained in sync with the remote version.

In order for synchronisation to occur syncmaps.php must be installed as a cron job
